A3 裸模型执行：全局视图与优化路线

目标：降低调度后的模型执行时延。本轮主线：按模型模块比较 P 侧 Device 算子与融合；Host 耗时对照暂缓。并行推进共享专家融合可行性、Device-Metadata 复用/融合，补采 A3 2P2D、P 侧 32DP×TP1、128k 输入。

已完成：执行链定位Worker、目标模型、采样与草稿边界已关联。
已完成：差异与成本识别融合、元数据、到齐等待和多流时序已有证据。

1. 裸模型执行全链：每项优化落在哪里

当前一个有效 step 的观测完成时长：734.612 ms。起点是 Worker.execute_model 进入，终点是本轮最后关联 NPU 任务完成。本轮 Device 首任务到末任务跨度：655.317 ms；不能把各阶段累加代替这两个实测值。

阅读方式：下图标执行位置；下表标具体任务，并链接到完整台账。同一阶段可包含多项优化；采集任务跨整个执行链。

本页排除前面的 tokenizer / Scheduler 排队；功能阶段存在重叠，734.612 ms 是当前采样窗口，不是完整请求 TTFT 或净算术时间。

阶段1 输入与元数据批次张量、SWA 窗口、Attention metadata、Engram 输入。Device-Metadata 复用 / 融合在这里。
阶段2 目标模型 40 层Attention 与 MoE 逐层执行，夹有 TP/EP 通信。Device 首 HC → 末 HC 约 455.8 ms；关注 Norm 融合、共享专家融合与 MoE 等待。
阶段3 主干收尾与采样HC collapse、aux buffer 写回、输出头与采样。主干收尾约 3.37 ms；关注 buffer 写回。采样另有重叠。
阶段4 草稿准备与 3 层上下文 KV、候选计算、草稿 MoE 与草稿输出头。仅 3 层设备包络约 36.82 ms；草稿 MoE 单独分析。
阶段5 输出与状态整理候选整理、异步输出；后续交还 EngineCore。本轮最后关联 NPU 任务在 +734.6 ms 完成；本阶段暂无优先改动。
阶段2 每层内部：HC Pre → Q/KV 投影、归一化与量化 → 压缩 / Indexer / Attention → 输出投影 → HC Post → HC Pre → 共享专家 / 路由专家 MoE → HC Post。通信与等待横跨这些环节；不能全部归到“算子计算慢”。

3. 投入顺序：采集与可行性核对并行 → 单项 A/B

采集线：G04，P0按 待填写的采集清单补 A3 2P2D / P32DP×TP1 / 128k；核对实际 EP、逐 step 工作量和专家负载后复表。

实现线：B03 / B11，P1并行核对 metadata 等价组和共享专家 INT8 融合接口；先做支持 / 不支持判断，再决定实现投入。

验收线：A3 单变量 A/B先微基准，再测同一 A3 基线的 Device 阶段墙钟、精度与服务指标；输出实测 Δms，不用跨硬件差值代替收益。

新采集门槛：写清两台 P 的 DP 总数与每个 engine 的配置；DP32 不自动代表 EP32。对齐真实 tokenizer token 数、每步 query / 历史 KV / 请求数、SWA / Engram / DSpark 开关。A3 强制均衡不能补出旧 A5 缺失的均衡样本；不匹配的 MoE 行保留限制。

预算参照：当前窗口缩短 5% 需净省约 36.7 ms。收益由 Device 模块差异与受控 A/B 确认；当前暂无收益实测或可信 A3/A5 倍率。

展开：融合差异、限制与证据入口
  • 已确认：A5 Q 路径有 40 次 RmsNormDynamicMxQuant；A3 独立 RmsNorm → DynamicQuant。A3 需保留 Indexer 使用的浮点 qr，不能直接改用 A5 MXFP 算子。
  • 已确认实现不同：A3 visible lens 重复展开，A5 使用专门 metadata 路径；需要先核对等价输入，不能要求 42 次全部变成 1 次。
  • 先评估支持：A5 KvCompressEpilogV2 和含共享专家参数的 MegaMoE，涉及不同 KV 格式、量化和硬件 ABI；不等于 A3 已具备可直接打开的同等融合。
  • 共享专家融合的源码门槛：固定 CANN 参考入口限制 W4A8MXFP，且检查 dynamic EPLB / mix placement / 冗余专家与共享输入；A3 INT8 不满足此量化入口，不能删除保护来强开。A5 捕获栈与实际参数可确认融合差异，其精确采集源码 SHA 仍待补。
  • 类型不同不自动等于融合：SparseFlashMla / MQ-SMLA 的名称变化，以及 TP4 → TP1 的显式通信减少，分别核对算法与拓扑。
  • 时间边界：734.612 ms 不含前置 Scheduler 排队，但包含入口后的前序设备工作影响；它不是完整请求 TTFT。EngineCore 完整 step 墙钟与最终 CPU 输出完成，本包未完整捕获。
    数据范围：P.rar 为 A3，vllm_profile_prefill-c192-bs12.zip 为 A5。数字主要来自 A3 DP0/TP0 的一个有效窗口；仅作路径成本样本，不代表整组 MoE 计算能力。734.6 ms 是 Worker 入口至本轮最后关联 NPU 任务的观察值，非完整 128k 请求 TTFT，也非净算术时间。
  • Q-norm 成本桶：40 次 1280 维 RmsNorm 为 1.137 ms，48 次同维度 DynamicQuant 为 0.907 ms，后者包含其他消费者的相关量化；2.04 ms 是候选桶，尚不是全部归属于 40 次 Wq_b 的精确配对成本。
  • 等待边界：现有数据未确认 CPU 抖动、固定慢卡或专家负载不均为根因；300 ms MegaMoE 和 35.76 ms 到达差均不能直接当收益。
