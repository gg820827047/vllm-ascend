展开时序证据、待优化点和验收方法
位置已确认的证据待验证的优化点验证方法与验收
输入与元数据 A3 样本中，Attention 元数据和 Replay 元数据的 Host 区间分别约 59.9 / 54.3 ms，伴随大量小算子。 检查重复字段能否复用，减少小算子及下发次数；参考 A5 的融合准备路径。 逐字段核对依赖，先改一处；同负载 A/B，检查准备阶段及整轮完成时间是否同时改善。
MoE 跨卡协同 A3 首层同轮 16 个 EP rank 到达相差 35.76 ms，结束仅相差 0.031 ms。算子驻留时长包含等待。 减少上游晚到与组内等待；区分准备慢、通信慢和专家负载不均。 扩展到全部有效轮次，对齐整组时间线，补采每专家 token 数；定位最后到达路径后再做针对性 A/B。
DSA 多流下发 DP2/TP2 的所查第 0/10/21 层，Q Norm 在 KV 结束后才提交；TP0 则提前提交。存在下发时序差异。 排查 Host 阻塞、元数据准备和提交顺序，恢复独立分支的重叠机会。 补采 CPU 调度与线程运行证据；同负载复测。验收整轮耗时，重叠率仅作解释指标。

以上是局部样本证据，区间不可相加或直接作为收益预算。现有数据尚不能确认 CPU 抖动、固定慢卡或专家负载不均是根因。

跨硬件对比：单算子测试可做，整模型结论仍需受控负载

单算子：固定 shape、dtype、布局及算法参数，预热后重复测量设备执行时间；MoE 还要固定路由和每专家 token 分布。单卡 GMM 测计算，完整 MegaMoE 需整组 EP 测计算与通信。结果反映硬件与算子实现的组合能力。

现有 A3/A5 trace：可核对融合方式、调用次数、数据搬运、流依赖及跨卡等待；因上下文、Runner、量化、拓扑和路由负载不同，不能用单个 rank 的耗时或整体耗时推导性能倍率，也不能据此判定 A5 更慢。

下一步：先形成一个可复现的 A3 优化闭环

① 固定 A3 基线固定查询长度、历史 KV 长度、批内请求及缓存状态，记录路由负载；以 Worker 入口至本轮关联设备任务完成为口径，处理前序队列影响，重复测量。
② 先验证一项融合/复用元数据优先；INT8 Q-norm 可并行做接口与正确性验证。每次只改一项，以整轮节省多少 ms、TTFT 和正确性验收。
③ 补齐算子与整模型对照从 trace 生成代表性单算子用例。A5 目前不可复跑，跨硬件测试待有资源后执行；能恢复相同逻辑工作量时，再建立整模型基线倍率。
可用于汇报：已有 profiling 确认了局部融合与实现差异，足以启动 A3 元数据和 Q-norm 融合验证，不必等待完整 A3/A5 性能倍率。下一阶段以 A3 同负载 A/B 闭环收益；跨硬件算子能力另用受控测试确认。
